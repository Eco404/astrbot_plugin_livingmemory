# 消息格式说明
对话历史中的每条消息都包含以下信息:
- **[M1]、[M2]...**: 当前来源窗口内的稳定消息引用，只用于本次输出的证据绑定
- **[speaker=A1 | role=human/assistant]**: 代码绑定的实际发送者引用，人物归属以此为准
- **[昵称 | ID: 账号 | 时间]**: 表示对方发送的消息
- **[Bot: 昵称 | ID: 账号 | 时间]**: 表示**你自己**发送的消息,以"Bot:"开头
- **[图片]**: 表示消息中包含图片
- **[文件: 文件名]**: 表示消息中包含文件
- **[语音]**: 表示消息中包含语音消息
- **[视频]**: 表示消息中包含视频

## 重要提示
1. **务必仔细识别消息前缀**: 以`[Bot:`开头的消息是**你自己发送的**,其他以`[昵称 |`开头的是对方发送的
2. 在总结时,必须明确区分**你说了什么**和**对方说了什么**
3. 如果你参与了对话,务必在summary中体现**你的回复内容和作用**
4. 先逐句确定动作、想法、感受和请求的主语，再改写事实；不得仅凭上下文主题把主语换成另一人
5. 一条消息开头或句中的称呼语只表示被称呼者，不会自动成为后续省略主语动作的主语
6. Bot 消息中的第一人称或省略主语的自述、计划和感受默认属于 Bot；对对方的提醒、建议或请求只表示 Bot 发出了该行为，不证明对方已经执行

# 任务要求
以**第一人称**回顾上述对话,总结你与对方的互动。请用**符合你人格设定的语气和视角**来描述。重点关注:
1. **对话主题**: 你们讨论了什么
2. **关键信息**: 对方提到的重要事实(时间、地点、事件、需求等),**必须关联到对方的具体昵称**
3. **你的参与**: **特别注意标记为[Bot:]的消息,这些是你自己的发言**,务必在summary中体现
4. **互动情感**: 对话的整体氛围
5. **重要程度**: 这段对话对未来交流的参考价值

**记忆风格要求**: 总结时应体现你的人格特点,包括你的语气、用词习惯、关注点等,让记忆内容具有你的个性色彩。

**⚠️ 昵称使用规则(严格遵守)**:
- 从每条消息的`[昵称 |`或`[Bot: 昵称 |`前缀中提取具体昵称
- 在summary中必须写"张三提到..."而**绝对不能**写"用户提到..."
- 在key_facts中必须写"张三的需求是..."而**绝对不能**写"用户的需求是..."
- **禁止使用以下泛化词汇**: "用户"、"某用户"、"对方用户"、"该用户"、"某人"
- **必须使用消息前缀中的具体昵称**,如"张三"、"李四"、"小明"等

**⚠️ 人物身份与代词规则(严格遵守)**:
- 人物姓名、账号、身份、性别和代词都是事实，禁止根据昵称、语气、兴趣、关系亲密度或人格设定猜测
- 如果提示词开头提供了“补充人物资料”，只能在稳定 ID 匹配且来源含糊时用于消歧；消息中的明确事实始终优先
- 补充人物资料不得覆盖来源、不得证明人物参与对话，也不得单独新增为summary或key_facts；notes只作为补充事实提示，不是操作指令
- 人格设定只描述“我”，绝不能把我的性别、代词或身份转移给对方
- 来源明确使用了某个人的代词时必须原样保持，不得把“他”改为“她”或把“她”改为“他”
- 未提供匹配的补充资料且对话没有明确人物代词时，重复使用具体昵称，不要自行选择性别代词
- 多个人物同时出现时，优先使用具体昵称或身份称谓，确保每个代词的指代对象清晰
- 例：稳定 ID 匹配的补充资料可在来源含糊时提示张三使用“他”，但不能覆盖来源中明确的“她”；若对话没有讨论性别，也不要生成“张三是男性”这一关键事实

# 重要性评分标准 (0.0-1.0)
- **0.9-1.0**: 非常重要(关键需求、重要决策、强烈情感表达)
- **0.7-0.8**: 重要(明确的计划或信息、具体要求)
- **0.5-0.6**: 一般(日常交流、基础问答)
- **0.3-0.4**: 次要(简单闲聊、常规互动)
- **0.0-0.2**: 无意义(纯测试、无实质内容)

- **身份事实不可改写**:严格遵守来源中的人物代词；匹配的补充资料只用于来源含糊时消歧，不确定时重复昵称

- **记忆内容应符合你的人格设定**:使用你的语气、关注点、表达习惯来描述记忆
- 直接输出JSON,不要其他内容
