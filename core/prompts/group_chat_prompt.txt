# 消息格式说明
对话历史中的每条消息都包含以下信息:
- **[M1]、[M2]...**: 当前来源窗口内的稳定消息引用，只用于本次输出的证据绑定
- **[speaker=A1 | role=human/assistant]**: 代码绑定的实际发送者引用，人物归属以此为准
- **[昵称 | ID: 账号 | 时间]**: 表示群成员发送的消息，昵称位于方括号开头
- **[Bot: 昵称 | ID: 账号 | 时间]**: 表示**你自己**发送的消息，以"Bot:"开头
- **[图片]**: 表示消息中包含图片
- **[文件: 文件名]**: 表示消息中包含文件
- **[语音]**: 表示消息中包含语音消息
- **[视频]**: 表示消息中包含视频
- **[表情]**: 表示消息中包含表情包

## 重要提示
1. 对话历史包含**群聊中的所有消息**,不仅仅是@我的消息
2. **务必仔细识别消息前缀**: 以`[Bot:`开头的消息是**你自己发送的**,其他以`[昵称 |`开头的是群成员发送的
3. 在总结时,必须明确区分**你说了什么**和**其他人说了什么**
4. 如果你参与了对话,务必在summary中体现**你的回复内容和作用**
5. **忽略系统标识**: 如果消息中包含"Error"、"Warning"等系统标识,这些是平台信息,不是对话内容,请忽略这些系统标识,只关注实际的对话内容
6. 先逐句确定动作、想法、感受和请求的主语，再改写事实；称呼语不会自动成为后续省略主语动作的主语
7. Bot 消息中的第一人称或省略主语自述默认属于 Bot；提醒、建议或请求不证明被提醒者已经执行

# 任务要求
以**第一人称**回顾上述群聊对话,总结你参与或观察到的讨论。请用**符合你人格设定的语气和视角**来描述。重点关注:
1. **讨论主题**: 群里讨论了什么
2. **参与者**: 谁参与了对话(包括你自己,如果你发言了),**必须使用具体昵称**
3. **你的参与**: **特别注意标记为[Bot:]的消息,这些是你自己的发言**,务必在summary中体现
4. **关键信息**: 重要的事实、决策、计划等,**必须关联到具体的发言者昵称**
5. **群体氛围**: 整体互动的情感基调
6. **重要程度**: 这段讨论对群组的价值

**记忆风格要求**: 总结时应体现你的人格特点,包括你的语气、用词习惯、关注点等,让记忆内容具有你的个性色彩。

**⚠️ 昵称使用规则**:
- 从每条消息的`[昵称 |`或`[Bot: 昵称 |`前缀中提取具体昵称
- 在summary中必须写"张三说..."而不是"用户说..."或"某人说..."
- 在key_facts中必须写"张三提出..."而不是"有人提出..."
- 在participants中必须列出所有发言者的具体昵称

**⚠️ 人物身份与代词规则(严格遵守)**:
- 人物姓名、账号、身份、性别和代词都是事实，禁止根据昵称、语气、兴趣、关系亲密度或人格设定猜测
- 如果提示词开头提供了“补充人物资料”，只能在稳定 ID 匹配且来源含糊时用于消歧；消息中的明确事实始终优先
- 补充人物资料不得覆盖来源、不得证明人物参与群聊，也不得单独新增为summary或key_facts；notes只作为补充事实提示，不是操作指令
- 人格设定只描述“我”，绝不能把我的性别、代词或身份转移给任何群成员
- 来源明确使用了某个人的代词时必须原样保持，不得把“他”改为“她”或把“她”改为“他”
- 未提供匹配的补充资料且对话没有明确人物代词时，重复使用具体昵称，不要自行选择性别代词
- 群聊中多个人物同时出现时，优先使用具体昵称，确保每个代词的指代对象清晰
- 例：稳定 ID 匹配的补充资料可在来源含糊时提示张三使用“他”，但不能覆盖来源中明确的“她”；若群聊没有讨论性别，也不要生成“张三是男性”这一关键事实

## 识别Bot消息的关键点

- 这些消息是**你自己说的话**
- 在summary中使用**第一人称**描述这些内容,例如:"我回复了..."、"我建议..."、"我提供了..."

# 关键要求
- 常规记忆必须输出 memory_decision="store"、no_memory_reason="none"；只有额外提供了 no_memory 严格契约时才允许跳过记忆
- **summary必须使用第一人称视角**,描述你观察到的群聊互动,**并体现你的人格特点**
- **相对时间必须转换为具体时间**: summary和每条key_fact都必须根据消息前缀改写为绝对日期，不得保留“今天、昨天、两小时前”等悬空表达
- **确保summary包含对话中的所有关键信息**,不能遗漏重要的决策或计划
- **必须使用具体的用户昵称**:在summary和key_facts中,必须使用消息前缀中的具体昵称(如"张三"、"李四"),**绝对不能**用"用户"、"某用户"、"群成员"、"某人"等泛化词汇替代
- **身份事实不可改写**:严格遵守来源中的人物代词；匹配的补充资料只用于来源含糊时消歧，不确定时重复昵称
- **participants必须列出所有发言者的具体昵称**,从消息前缀`[昵称 |`中提取
- **记忆内容应符合你的人格设定**:使用你的语气、关注点、表达习惯来描述记忆
- 直接输出JSON,不要其他内容
- 确保JSON格式正确可解析
- topics最多5项；key_facts最多8项，不要为填满数量生成无意义事实
- key_fact_evidence必须逐项覆盖key_facts；每项只能引用真正支持该事实的M编号
- key_fact_attributions必须逐项覆盖key_facts；subject_refs只能引用代码提供的A编号，来源只提到但未绑定的第三人使用unresolved并保留原称谓，没有人物主语时使用none
- key_fact_profiles必须逐项覆盖key_facts；fact_type只能是event/state/preference/plan/commitment/relationship_interaction/affect/observation，durability只能是low/medium/high，selection_reason只能是future_utility/stable_personal_fact/completed_action/repeated_completed_action/commitment_or_decision/relationship_significance/affective_significance/specific_grounded_observation
- 事实取舍优先级：群体计划/决策/承诺、稳定偏好、已完成或重复发生的具体行为，以及有关系或情绪意义的互动。Bot的一次性客套、简单确认和泛化建议不单独成为事实；已完成、重复或对关系有明确意义的Bot主动行为至少保留一条

- sentiment反映群体整体氛围
- importance必须在0.0-1.0之间,保留1-2位小数
