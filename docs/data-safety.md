# 数据安全与迁移

## 数据库

插件数据目录主要包含：

| 数据 | 作用 |
| --- | --- |
| `livingmemory.db` | Timeline、Topic、用户画像、人格关系、原子、构建任务与诊断 |
| `conversations.db` | 原始会话消息与总结位置 |
| 向量索引 | 可重建的运行时检索产物 |
| 人物资料与设置覆盖 | 补充消歧信息和 WebUI 参数 |
| 备份目录 | 版本变化、迁移和定时备份 |

SQLite 是正式数据的权威来源，FAISS 索引可以丢弃并重建。

## 数据库版本

3.8.x 使用数据库 v10.4。正式迁移主路径为：

```text
v8 -> v9 -> v10 -> current v10.x
```

小版本以文本存储，避免把 `v10.10` 当成浮点数。迁移不会调用 LLM，也不会凭空生成 Topic；需要新语义产物时，由用户在升级后执行构建或维护。

v10.3 升级到 v10.4 一次性创建用户画像、来源、冲突、关系 revision、账号绑定、共享组、维护任务和旧 Timeline 身份解析旁表。迁移不会扫描或回填旧 Timeline，也不会修改 Timeline、Topic、会话或补充人物资料。升级后默认只处理新的私聊 Timeline；旧历史必须由管理员显式扫描或重建。未发布的开发期中间 schema 不属于正式迁移路径，测试数据在发布前清空重建。

显式历史扫描会优先使用原生 `role_bindings`。旧 Timeline 缺少该字段时，只组合相同 Bot/persona、相同私聊目标、同 session 稳定 actor、明确的人类消息 sender 和规范平台等精确证据；可以唯一确定时自动归入对应用户，不能唯一确定时进入人工审查。审查记录位于派生旁表，支持人工绑定、忽略和恢复，原 Timeline metadata 始终不变。

## 用户画像隐私边界

- 只有可解析为稳定平台账号的私聊用户才自动建档；群聊、昵称和临时 session 不建档、不注入。
- 跨平台账号不会自动合并。人工绑定保留每条事实的原始账号来源，解绑后据此重新投影。
- 敏感行为推断默认关闭且有更高证据门槛；密码、Token、API key、私钥和验证码始终拒绝保存。
- 冲突事实暂停注入，不能静默覆盖。人工裁决和后续自动复核都保留来源与覆盖记录。
- 缺少消息级归属的旧 Timeline 摘要不能单独形成有效客观事实；保留的候选保持 pending。主观关系可将其作为弱历史，但不能据此触发重大事件或剧烈变化。
- 客观画像和人格关系不会输入 Timeline 总结、Topic 构建或知识图谱，避免派生内容自我复制。
- Timeline 与维护任务不保存 persona 提示正文。关系维护在执行时读取当前 persona，数据库只在关系状态和 revision 中保留摘要签名用于审计；调用期间人格变化会使本次结果失效并重试。
- 被动注入和主动工具都只能读取当前稳定私聊用户；主动工具还必须显式请求 `include_user_profile=true`。

## 删除语义

| 操作 | 保留内容 |
| --- | --- |
| 清理已总结的聊天记录 | Timeline、Topic 与可用来源快照 |
| 删除全部聊天记录 | Timeline、Topic；失去没有快照的原始消息补证能力 |
| 删除 Timeline | 移除来源并局部修复或归档失去来源的 Topic |
| 清空 Topic | Timeline 保持不变，可重新全量构建 |
| 重置用户画像 | 清除派生事实，保留启用状态；默认只处理之后的新变化 |
| 删除并停用用户画像 | 删除画像和关系状态并阻止自动重新建档，直到管理员恢复 |
| 完整删除会话记忆链 | 删除会话、Timeline，并同步处理 Topic 派生链 |

## 备份与恢复

- 插件版本变化时创建版本标记备份。
- 数据库迁移前按配置备份。
- 每日维护可创建定时备份并清理过期副本。
- 高风险 WebUI 操作提供预览和确认，但仍建议用户在批量删除前单独备份插件数据目录。

## 数据库健康检查

维护中心检查 `integrity_check`、外键约束、共享图谱边来源和记忆来源链。检查不会修改数据；可修复项目必须由用户勾选，执行时显示独立进度。

压缩数据库会在独立连接执行 `VACUUM`，短时间锁定数据库。删除中间数据后文件不会立即缩小，只有压缩成功才会把空闲页归还磁盘。

画像生命周期扫描会按设置推进过期事实状态、清理超过保留期的已完成任务，并删除可由较新 revision 确定重建的旧投影事件。当前投影、仍被事实引用的来源以及关系 revision 的审计信息不会作为普通投影压缩对象删除。
