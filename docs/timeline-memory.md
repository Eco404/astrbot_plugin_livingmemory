# Timeline 记忆

Timeline 按时间保存一次连续对话中发生的事情。它是用户可编辑的正式来源，也是 Topic 重建、人物追溯与动态重要性的基础。

## 生成边界

Timeline 可以由三种方式产生：

| 方式 | 适合场景 |
| --- | --- |
| 基础轮次与话题接续 | 持续活跃的长对话 |
| 空闲触发总结 | 话题自然结束，达到最小轮数后长时间没有新消息 |
| 手动或 Agent 写入 | 用户明确要求记住，或需要立即固化的信息 |

空闲总结会在插件启动后继续扫描：只要最后消息已经超过空闲时间且未总结轮数达到最小值，即使空闲时间点发生在插件关闭期间，也会在恢复后进入检查。

## 话题接续

话题接续只调整持续对话中的基础轮次边界，不会阻止空闲、手动或失败重试总结。达到基础轮次后：

- 当前窗口允许同时存在多个候选话题；
- 新对话与任一已有话题语义接近时，延后总结；
- 新对话未命中任一已有话题时，只总结它之前的内容，将它留作下一个窗口的起点；
- 达到强制总结上限后，即使话题仍在延续也会总结，避免窗口无限增长。

召回阶段已经计算过的当前消息向量会被暂存在原始会话库中。话题接续检查会优先复用兼容的向量，只为缺失部分调用 Embedding；窗口总结或原始消息被清理后，对应暂存也会删除。如果 Embedding 不可用，系统会回退到按轮次总结，不会因边界判断失败而丢失记忆。

## 结构化内容

Timeline 不只是摘要文本。新记录会尽量保存：

- `canonical_summary` 与可注入正文；
- 带时间锚点的关键事实与主题；
- 重要性、情绪、记忆类型与质量状态；
- 会话、人格、参与者与叙述者绑定；
- 来源消息范围或结构化来源快照；
- 稳定 `memory_uid`、revision 与关联 Topic 数量。

## 质量处理

完全无意义的窗口可以输出合法的 `no_memory`，推进总结位置但不创建 Timeline。可确定修复的问题会使用来源数据纠正；仍有质量风险的结果可以保留并打上低质量标识，之后在维护中心筛选并同 ID 重构。

## 编辑、暂存与重构

直接编辑 Timeline 时可以选择：

- 立即保存，并按范围同步关联 Topic；
- 暂存修改，在 **维护 → Timeline 维护** 中批量确认；
- 从原始消息或来源快照执行同 ID 重构。

批量重构会先完成所选 Timeline，再统一同步受影响 Topic，避免逐条重构产生顺序依赖和重复派生。

## 动态重要性

Timeline 的基础重要性来自总结或用户修正；有效重要性还会考虑时间衰减和访问强化。Topic 的动态重要性从其来源 Timeline 与证据强度投影计算，不累计回写，从而避免两套衰减造成误差。
