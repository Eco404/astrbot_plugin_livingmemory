# 整体架构

LivingMemory 以 Timeline 作为唯一可编辑来源，并从同一 revision 链并行派生 Topic 与用户画像。Topic 负责跨时间组织和相关性召回；用户画像负责当前私聊对象的确定性事实与 persona 关系连续性。两条路径互不回写，也不会把派生内容再次送入 Timeline 总结。

![LivingMemory 整体架构](./assets/images/architecture-overview-zh.svg){.diagram}

## 数据层级

| 层级 | 主要内容 | 是否直接编辑 | 主要用途 |
| --- | --- | --- | --- |
| 原始会话 | 消息、发送者、角色、时间 | 否 | 总结证据、按需补证、会话审计 |
| Timeline | 摘要、事实、主题、情绪、时间与人物绑定 | 是 | 保存按时间发生的经历 |
| 正式片段 | 单一检索意图、事实、人物、情绪与来源 | 否 | Topic 构建与精简补充 |
| Topic | 主题正文、独立原子、人物索引、相关话题 | 否 | 跨时间归并与主要召回 |
| 用户画像 | 当前用户的客观事实与 persona 关系状态 | 仅通过治理操作 | 精确私聊作用域内的对象理解与态度连续性 |

## 用户画像派生层

用户画像与 Topic 平行地从 Timeline 派生，不是第三种可自由编辑的来源记忆：

```text
稳定私聊 actor + Timeline revision
  -> 客观事实来源与冲突投影
  -> Bot/persona/user 画像 revision

新用户侧互动
  -> persona/user 关系 revision

当前私聊请求
  -> 加载对应作用域
  -> 在硬字符预算内临时注入
```

客观事实保留 Timeline 原始关键事实正文，维护模型只能决定准入、分类、置信度、重要性、冲突和生命周期，不能重写来源文本。只有 `active` 且当前有效的事实可以注入；`pending`、`conflict` 和 `stale` 只进入维护流程。Timeline 编辑、重构、归档或删除时，投影事件会撤销旧 revision 的贡献并原子发布新画像；旧画像在任务失败时继续可用。

关系状态是当前 persona 对逻辑用户的主观派生，包括六个连续维度、少量标签、第一人称叙述和短期余韵。它可以读取非敏感客观画像作为背景，但必须由新的用户侧互动更新，不能反向生成客观事实，也不能输入 Timeline 总结形成反馈循环。Timeline、投影事件与维护任务都不保存人格正文或人格快照；关系维护在执行时读取当前 persona，发布前再次校验其 digest，期间配置变化则拒绝旧结果。关系状态和 revision 仅保留 persona digest 作为一致性与审计依据。

事实维护按 Timeline 数、候选事实数和提示字符三重边界分批，已有事实与历史行为证据作为可裁剪上下文，来源候选不会因预算被静默丢弃。事实检查点失败时关系阶段不运行；显式历史重建先完成全部事实，再读取截至重建边界的完整历史，按可配置关系批次保持时间顺序并最终原子发布一次。周期性生命周期扫描负责事实状态转换、已完成任务保留和可重建旧投影压缩，避免聊天增长令维护上下文和数据库无限膨胀。

稳定账号映射到逻辑用户。默认客观事实按 Bot 账号、persona 和逻辑用户隔离，显式共享组可以让同一逻辑用户的指定作用域共用客观事实；关系状态始终按 persona 隔离。昵称不参与身份合并，跨平台账号只允许管理员人工绑定。运行时画像按当前私聊的 Bot、persona 与稳定 actor 精确加载，不依赖 Topic 是否召回成功。

## 为什么不让 Timeline 与 Topic 共用原子

Timeline 原子描述某次总结窗口中的事实，Topic 原子则描述跨片段归并后的稳定事实。如果直接共用，Topic 合并、拆分或重新表述时会反向修改来源层，也无法独立记录 Topic 的置信度和来源覆盖。

当前设计保留两套原子，并使用以下关系追溯：

```text
Topic atom
  -> formal fragment
  -> Timeline UID + revision
  -> Timeline atom / source fact key
  -> source window or source snapshot
```

## 稳定身份与版本

- Timeline 使用稳定 `memory_uid`，物理文档 ID 可以改变。
- 每次正文或来源变化递增 revision。
- 正式片段拥有稳定逻辑 ID 与独立 revision。
- Topic 使用稳定 UID；更新时原子发布完整新快照。
- 构建检查点绑定输入、配置、Prompt 与模型签名，变化后只复用仍然有效的阶段。

## 人物与情绪

消息发送者与 Timeline `role_bindings` 提供稳定人物锚点。正式片段只能引用输入中允许的 actor ref，不按昵称跨片段猜测身份。Topic 人物和事实人物关系存入独立关系表，详情页可追溯到片段与 Timeline。

情绪不是只保留一个正负标签。正式片段与 Topic 保存情绪事件、强度、目标与来源；召回时可作为轻量补充，避免主题摘要把互动中的感情色彩完全抹平。

## 图谱的位置

图谱仍可从 Timeline 事实生成实体与关系，并参与兼容的 Timeline 双路检索。但在当前 Topic 优先架构中，图谱不是 Topic 构建或 Topic 召回的权威来源。主要链路应以 Timeline、正式片段、Topic 及其来源关系为准。
