# 配置参考

LivingMemory 将配置分成两层：AstrBot 插件配置只保留首次启用所需的稳定开关和凭据；运行参数统一在插件 WebUI 的 **设置** 页面管理。

## 插件配置

| 分组 | 主要内容 |
| --- | --- |
| 模型提供商 | LLM、Embedding、可选 AstrBot Rerank Provider ID |
| Topic 记忆 | 构建开关、Topic 优先召回、自动维护 |
| Cloudflare Rerank | 内置客户端开关、Account ID、Token、模型与 API 地址 |
| 会话管理 | 是否捕获群聊全部消息 |
| Agent 工具 | 主动回忆与主动写入工具开关 |
| 图记忆 | 兼容 Timeline 图路和事实原子开关 |
| 迁移与备份 | 自动迁移、迁移前备份、每日备份 |

留空的 LLM 与 Embedding Provider ID 会回退到 AstrBot 默认模型。内置 Cloudflare Rerank 配置完整并启用时，优先于 `rerank_provider_id`。

## WebUI 设置分类

| 分类 | 示例 |
| --- | --- |
| 召回 | 候选倍率、最低相关度、相对门槛、MMR、跨轮权重 |
| 生成 | 基础总结轮次、话题接续、空闲总结、来源快照阈值 |
| 会话 | 缓存上限、上下文窗口、原始消息保留策略 |
| 注入 | 注入位置、旧注入清理 |
| 生命周期 | 衰减、访问强化、低重要性清理 |
| Topic 构建 | 批量、并发、匹配、合成、审查阈值 |
| 用户画像 | 自动建档、事实准入、敏感推断、冲突、时效、注入和人格关系 |
| 模型与性能 | 超时、缓存、索引重建与 Cloudflare 行为 |
| 维护 | 备份保留期、已完成构建中间数据自动清理 |

运行参数以稀疏覆盖保存。显示“默认”表示使用代码当前默认值；“自定义”表示用户保存了覆盖。单项恢复默认会删除覆盖，因此以后升级到新的代码默认值时能自动生效。

设置页会隐藏当前不生效的从属项。例如关闭空闲总结后，不再显示空闲时间和最少轮次；关闭话题接续后，不再显示强制总结上限。被隐藏的已保存值不会被删除。

## 用户画像设置

“设置 -> 用户画像”包含该功能的全部运行参数：

| 分组 | 主要控制项 |
| --- | --- |
| 基础功能 | 客观画像、私聊自动建档、人格关系和私聊注入开关 |
| 模型与任务 | 专用或回退 LLM Provider、并发、Timeline/候选/提示三重批量边界、调用总超时、已有事实上下文上限、持久任务重试和退避 |
| 事实准入 | 事实置信度、长期画像价值与 pending 保留期 |
| 行为推断与敏感信息 | 独立 Timeline 数、证据跨度、置信度、跨批证据池、候选与补证边界、证据时区及敏感推断开关 |
| 冲突与候选 | 后续新证据数量、跨度和自动裁决优势 |
| 时效与重要性 | 偏好、习惯、状态、计划和交流偏好的固定与复核期限 |
| 注入 | `layered` / `compact_snapshot`、总字符、关系预留和单事实上限 |
| 人格关系 | 主观叙述长度、余韵期限、五档变化敏感度和四档行为模式 |
| 高级恢复 | 启动恢复、生命周期扫描、已完成任务保留、投影压缩和关系重建批次 |

默认只根据新产生的私聊 Timeline 维护画像，不自动回填升级前历史。`sensitive_behavior_inference_enabled` 默认关闭；无论该开关如何，密码、Token、API key、私钥和验证码都不会进入画像。

关系状态和客观事实分别调用维护模型。每次业务调用只允许 AstrBot Provider 进行一轮传输尝试，并受默认 180 秒总超时约束；失败由持久任务默认自动重试 3 次，耗尽后在维护页人工重试。响应成功但 JSON、来源引用或发布契约不合规时，默认再进行 2 次携带允许短引用白名单的契约纠错，仍不放宽校验。事实维护同时受 8 条 Timeline、16 个候选事实和 16000 提示字符限制，并最多提供 200 条仍需维护的已有事实；提示超限时先裁剪已有事实，再裁剪历史行为证据，不丢弃本批候选。跨时间行为先发现候选，再只判定达到确定性数量与跨度门槛的候选；语义补证和时间邻域均有独立上限，默认以 `Asia/Shanghai` 将原始时间戳转换为可读观察时间。关系行为模式只控制画像如何影响回复，不会把人格主观叙述提升为客观事实。

关系维护不保存 persona 提示快照，而是在执行时读取当前 persona。发布前会再次校验人格摘要签名；若调用期间人格发生变化，本次结果作废并重试。同一 persona ID 的提示修改会在后续有新用户侧证据时协调主观叙述和标签，但不能单独改变长期关系维度。

字符预算是硬上限：默认总注入 800 字符，其中关系优先预算为 350 字符，单条事实最多 200 字符。事实与关系任何一侧未用完的预算都会回流给另一侧。跨字段保存会校验关系预留不高于总预算、固定期限不高于复核期限，以及敏感推断门槛不低于普通行为推断门槛。

默认每 24 小时扫描一次画像生命周期：到期的 active 事实转为 stale，pending 和长期 stale 事实归档；超过 30 天的已完成任务、已被更新 revision 取代的旧投影事件和无引用失效来源会被清理。显式历史重建先完成全部客观事实批次，再读取截至该次重建边界的完整事件历史，并默认每 32 条有意义 Timeline 维护一次关系，最后只发布一个关系 revision。

## 推荐起步策略

- LLM 并发先保持 `1` 或 `2`，确认 Provider 限流后再提高。
- Rerank 并发从 `1` 开始；429 表示应降低并发或等待容量恢复。
- 不要仅因为一次数据集测试就大幅降低合并阈值。
- 保持自动备份和构建中间数据自动清理开启。
- 原始消息自动删除默认关闭，先通过会话审计确认影响。

::: warning 配置不是构建快照
召回参数通常立即生效；Topic 构建参数只影响新任务。正在运行或断点继续的任务使用创建时保存的配置和模型签名，避免同一任务混用两套规则。
:::
