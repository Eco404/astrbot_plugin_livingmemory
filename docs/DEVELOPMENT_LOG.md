## [3.8.1] - 2026-08-12

### WebUI

- 在侧边栏 Topic 记忆下方新增独立的只读用户画像页面。页面复用现有画像详情接口，展示作用域状态、客观事实、待复核事实、revision、实际注入预览、人格关系维度、标签和主观叙述；所有治理操作仍保留在维护页。
- 用户画像维护页新增构建候选列表。候选必须来自私聊 Timeline，具备稳定 human actor 和精确 Bot/persona 作用域，且尚未建立画像；服务端在提交时重新校验候选指纹，再创建作用域、回填历史投影事件并调度正常维护。
- 已存在但尚无事实和人格关系的作用域会显示“从历史构建”；无任何画像时也会直接提供构建入口。身份歧义记录不会成为候选，仍进入现有身份审查流程。
- 加宽维护页状态筛选控件；设置页的用户画像栏目移动到 Topic 右侧；补充中文、英文和俄文界面文本及中英文 WebUI 文档。

### 测试

- 补充构建候选身份边界、候选指纹提交、历史回填、只读页面和导航顺序测试；使用 v10.3 真实数据库的临时迁移副本验证旧 Timeline 候选发现，不修改原数据库。
- 全量后端测试、前端测试、文档构建、隐私扫描、JavaScript/Python 语法检查和差异格式检查通过。

## [3.8.0] - 2026-08-11

### 新增

- **可溯源客观用户画像**：具有稳定 actor ID 的私聊用户在新 Timeline 成功保存后自动建档。画像事实保留原始关键事实正文、Timeline UID/revision、事实位置、声明类型、归属置信度和原始账号来源；群聊、昵称和临时 session 不用于建档或合并。
- **事实准入与生命周期**：稳定信息、偏好、当前状态和计划仅接受明确自述或直接观察，并把事实真实性与长期画像价值分开评分；一次性事件和中低耐久偏好只保留为未归纳行为证据。习惯和交流偏好允许跨批引用历史证据，但仍必须满足可配置的独立 Timeline 数量、时间跨度和置信度门槛。安全秘密始终拒绝，敏感行为推断默认关闭。
- **冲突与后续证据**：冲突事实暂停注入并保留双方来源。管理员可以选择胜出事实、保持暂停或排除；后续相关 Timeline 仍会参与复核，在满足证据门槛后可自动 supersede 或解除冲突。
- **persona 人格关系状态**：每个 persona 与逻辑用户独立保存熟悉、信任、亲近、舒适、紧张和关切六维状态、开放式态度标签、第一人称主观叙述与有期限的短期余韵。关系维护必须含新的用户侧互动，不能由 Bot 自己的回复循环强化；主观字段聚焦态度和关系动态，不复述具体私密事实。
- **私聊注入与主动工具**：客观事实和关系状态使用独立的、可确定清理的 data-only 标记注入当前私聊请求；即使普通召回关闭或无结果也可生效。主动召回工具只在调用方显式请求 `include_user_profile=true` 时返回当前稳定用户画像，不能查询任意用户。
- **用户画像维护页**：新增画像搜索、状态筛选、实际注入预览、Timeline 来源跳转、事实治理、冲突裁决、关系编辑与 revision 回滚、断层提示、历史重建、账号绑定/解绑、客观共享组和任务重试。旧 Timeline 身份审查支持扫描、绑定当前画像账号、可逆忽略和恢复考虑；危险操作使用证据指纹和乐观锁拒绝过期提交。
- **可审查的旧 Timeline 身份解析**：显式重建优先使用原生 `role_bindings`；旧记录缺失该字段时，仅组合相同 Bot/persona、精确私聊目标、同 session 稳定 actor、明确人类 sender 和规范平台。唯一结果直接自动归属，证据缺失或冲突进入持久审查队列，不按昵称或跨平台猜测。解析结果保存在旁表，原 Timeline metadata 不改写；会话证据按 500 条分批读取并兼容旧 schema 缺列。
- **旧摘要弱证据策略**：自动确定用户不等于恢复消息级事实归属。旧摘要候选置信度最多 0.45，始终先进入 pending，不能单独 supersede、制造冲突、确认现有事实或成为代表来源。人格关系允许利用旧摘要保持宽泛连续性，但首次维度上限为 0.35、仅旧摘要更新限幅为 0.04，且不能触发重大事件。
- **当前 persona 关系维护**：Timeline 投影事件和维护任务不再保存 persona 提示正文。关系阶段执行时按作用域读取当前 persona，发布前再次校验摘要签名；调用期间人格变化会拒绝旧结果并重试。同一 persona ID 的提示变化会在后续有用户侧证据的维护中协调主观叙述和标签，但不会单独改变六个关系维度。
- **有界维护与存储**：事实维护默认只向模型提供 200 条 conflict/active/pending/stale 记录；响应成功但违反 JSON 或来源引用契约时，默认用明确候选、supporting evidence 和现有事实 UID 白名单纠错 2 次，仍不放宽校验。生命周期扫描定期转换到期事实、清理完成任务和可重建旧投影。历史投影读取取消 10,000 条总量截断，关系重建按默认 32 条 Timeline 分批处理并最终只发布一次。
- **完整运行设置**：所有准入门槛、敏感推断、冲突复核、时效、字符预算、关系敏感度、行为模式、并发、重试和恢复参数统一位于“设置 -> 用户画像”，继续使用稀疏覆盖和交叉校验。设置修订提升到 5；注入总上限保持 800，关系优先预算为 350 字符并允许事实与关系预算双向回流。

### 架构与隔离

- 客观事实默认按 `Bot 账号 + persona + 逻辑用户` 隔离，只能由管理员为同一逻辑用户显式创建共享组；人格关系始终保持 persona 隔离。
- 跨平台账号禁止自动合并。人工绑定前预览事实、冲突与作用域影响；解绑按每条来源保存的原始 actor ID 重新投影，不能复制合并快照。
- Timeline 继续是可编辑来源层。画像不会输入 Timeline 总结、写入 Topic 或同步到知识图谱，避免派生结果自我复制。

### 兼容性

- 数据库由 v10.3 一次升级到 v10.4：同一迁移新增用户、账号、作用域、事实、来源、冲突、覆盖、共享、关系 revision、投影事件、持久化任务和 `user_profile_timeline_identities` 派生身份审查旁表。未发布开发期中间 schema 不提供回退，测试库发布前清空重建。
- 迁移只创建结构，不扫描旧 Timeline、不调用 LLM、不改写 Timeline/Topic/会话，也不自动历史回填。升级后的新变化会正常维护；旧历史只能由管理员在维护页显式扫描或重建。
- 插件版本变化仍在迁移前备份 `livingmemory.db`、会话库、图数据库和可重建索引。

### 测试

- 新增数据库迁移、稳定身份、投影幂等、事实准入、冲突、关系维护、注入预算、主动工具、账号绑定/解绑、客观共享隔离、维护 API、前端滑块与事实恢复测试。
- 完整回归为 1096 项 Python 测试通过，包含显式真实 v10.3 数据路径的 2 项集成测试；10 项 Node 前端测试、Python 编译、隐私扫描与 VitePress 中英文文档构建通过。
- 使用真实 v10.3 插件数据完整副本执行 v10.4 迁移：全部旧表行数保持不变，重复迁移幂等，`integrity_check` 与外键检查通过，并在副本中完成身份旁表、画像事实和关系 revision 写入；原始数据库哈希保持不变。
- 在 conda `astrbot` 环境和官方 AstrBot 4.27.2 中，真实数据的 71 条私聊 Timeline 包含 31 条原生身份记录，其余 40 条均由同 session 稳定账号与会话消息证据自动确定归属，0 条待审查；回填 71 条后再次预览缺失数为 0。
- 使用真实 API、真实 v10.3 数据和当前 persona 完成最终端到端验收：9 个维护批次、18 次维护调用全部成功，0 任务错误；形成 5 条有效事实和 4 条仅供管理员复核的 pending 候选，关系发布到 revision 9。最终私聊注入包含 5 条事实和人格关系，共 615/800 字符。
- 独立审计的 groundedness、persona consistency、proportionality、continuity value 和 privacy safety 分别为 0.86、0.89、0.79、0.84、0.86。低级别提示主要涉及避免无关主动提及生活隐私、避免详尽人格压过当前用户意图；地点、学校和低置信偏好只存在于 pending，不作为运行时事实注入，因此不为单一样本继续调整全局门槛。
- Timeline 投影事件和维护任务均未持久化 persona 正文或快照，任务表也不含 persona 正文列；关系 revision 的摘要签名与执行时当前 persona 一致。注入总上限保持 800，关系优先预算由 300 调整到 350 且双向回流。数据库与凭据文件哈希前后不变，所有测试写入只发生在自动删除的临时副本中。

## [3.7.0] - 2026-08-10

### 变更

- **Timeline 精确窗口补偿**：总结失败时持久化原窗口边界、触发来源、人格和后续到期窗口；服务恢复后从最早失败窗口开始，按原顺序逐段补回，不会把多个窗口折叠成一个超长总结。
- **可恢复的总结冷却**：自动重试达到单轮上限后进入最长一小时的冷却，不再永久阻塞；产生新的到期边界或检测到 Provider、模型配置变化时立即重试最早窗口。单次调用最多处理 64 个积压窗口，避免长期占用任务循环。
- **增量 Topic 整批分配**：先计算整批正式片段与已有 Topic 的匹配结果，再统一分配、合成和发布；多个组件命中同一 Topic 时只合成一次，消除逐组件发布产生的顺序依赖。
- **受限的事件连续性辅助**：同一 Timeline 和时间簇内至少两个明确锚点才可辅助模糊片段；语义相关度仍须达到下限，连续性加分最高 0.15，时间邻近度按间隔指数衰减且最高 0.05，不能覆盖明显的语义冲突。
- **匹配诊断与设置契约**：诊断记录基础分、时间邻近度、连续性加分、锚点数量和最终决策；Topic 设置修订提升至 11，并增加时间窗口、锚点优势、最少锚点数、连续性加分和救援区间参数。

### 兼容性

- 数据库仍为 v10.3，无需迁移。旧 `pending_summary` 中已经进入阻塞状态的窗口会按新规则自动恢复；历史 Topic 版本不会被自动改写，后续增量构建和维护任务使用新匹配策略。

### 测试

- Timeline 总结覆盖旧阻塞恢复、Provider 切换、后续边界入队及多窗口按序补偿。
- Topic 匹配覆盖主导锚点、拆分事件不强制聚合、时间衰减、整批合成与发布。
- Timeline 与 Topic 两组专项测试共 133 项通过。

## [3.6.0] - 2026-08-05

### 变更

- **Topic 本地重要性投影（数据库 v10.3）**：Topic 基础重要性只由自身正式片段、事实重要性和置信度聚合，不再继承整条 Timeline 的绝对分数。
- **有界 Timeline 生命周期参考**：来源 Timeline 的调用、衰减与活跃状态仅在 15% 范围内衰减 Topic，不能将 Topic 抬高到自身语义基准之上；Topic 自身的访问次数和时间衰减继续独立生效。
- **事实级来源贡献**：一个 Topic 关联多条 Timeline 时，依据实际支撑事实的重要性、置信度与溯源关系分配贡献权重；Topic 被调用时也优先刷新贡献最高的 Timeline。
- **README 入口调整**：中文内容改为根目录 `README.md`，英文内容迁移至 `README_en.md`，三语切换链接同步更新。

### 兼容性

- v10.2 升级到 v10.3 时，优先使用现有 Topic 原子和事实来源回填 Timeline 贡献权重；无事实级溯源的旧数据回退到现有链接权重或等权分配。迁移不改写 Topic 正文、事实和来源关系。

### 测试

- 新增 Topic 重要性隔离、零贡献来源、事实级权重与 v10.3 迁移回填测试。
- 完成后端、前端、Python 编译与 VitePress 文档构建验证。

## [3.5.6] - 2026-08-04

### 新增

- **Timeline 批量编辑**：Timeline 列表可对所选记忆统一修改重要性、活跃/归档状态或记忆类型，并可记录本次操作原因。
- **批量操作审计**：批量修改沿用单条编辑的历史记录结构，保存修改前后值、时间和原因；无效 ID 与单条失败会在响应中单独返回。

### 变更

- **派生 Topic 状态同步**：归档 Timeline 时同步更新逻辑记忆注册状态，标记关联 Topic 来源并进入修复流程；重新激活时安排局部 Topic 维护，避免 Timeline 与 Topic 可用状态不一致。
- **接口与交互边界**：批量编辑限制为单次 500 条，不允许借批量状态修改执行删除；重复提交会被拦截，部分失败时只保留失败条目供用户复核。
- **正文契约说明**：文档明确 `canonical_summary` 保留模型摘要并拼接关键事实，当前 Timeline 检索与注入均使用该富正文；`persona_summary` 保留未扩展的原始摘要。
- **兼容性建议**：文档推荐 `faiss-cpu>=1.14.3`，继续排除已知不兼容的 `1.14.2`，但不提高硬性最低版本。
- **项目归属**：插件发布作者更新为 `econeco`，三语 README 保留原仓库和原作者署名。

### 测试

- 新增批量重要性修改、归档确认、重复提交和部分失败的前端回归测试。
- 新增 Timeline 归档/激活与 Topic 同步测试，并完成桌面、手机布局检查和 VitePress 构建验证。

## [3.5.0] - 2026-08-02

### 新增

- **持久化索引维护状态（数据库 v10.2）**：新增 `document_index_state`，按索引类型保存 generation、Provider 签名、结构版本、任务状态、断点和错误。FAISS 全量重建支持取消后续建，完成前使用临时目录，成功后再切换正式索引。
- **持续集成工作流**：新增面向 `master`、`dev` 和 Pull Request 的 Python 3.12、Node 22、前端回归测试及 VitePress 构建检查。
- **可重复的发布说明生成器**：发布前统一校验 `metadata.yaml`、`package.json`、`main.py` 与备份管理器中的版本号，并从 `CHANGELOG.md` 精确提取当前版本内容作为 GitHub Release 描述。

### 变更

- **BM25 原子重建**：在影子表中完成 FTS 重建与校验后再切换正式表，失败时保留原有可查询索引。
- **启动期索引维护后台化**：插件先完成初始化，再在后台检查签名和重建索引；Provider、模型或向量维度变化会触发完整 FAISS 重建，维护期间发生的写入在结束前再次对账。
- **FAISS 兼容性诊断**：仅对 CPU 指令集或共享库类故障使用通用回退，对 `SuperKMeans` 等 Python 绑定与二进制版本不匹配问题输出明确诊断；依赖排除已知不兼容的 `faiss-cpu 1.14.2`。
- **Release 工作流**：不再依赖 GitHub 自动生成发布描述；现有标签不会被覆盖，手动执行也只会为尚不存在的版本标签发布。

### 修复

- **Timeline 列表并发覆盖**：只允许最后一次请求更新页面，较早返回的结果或错误不会覆盖新筛选条件下的数据。
- **虚拟滚动状态过期**：滚动处理始终读取当前列表状态，并使用真实占位行维持表格高度，避免筛选后复用旧数组或出现布局跳动。
- **侧边详情面板可访问性**：关闭时同步设置 `inert` 和 `aria-hidden`，打开后恢复交互，避免隐藏面板继续接收键盘焦点。

### 测试

- 新增 BM25 失败回滚、Embedding 签名变化、FAISS 强制重建和取消续建测试。
- 新增前端乱序请求、虚拟滚动状态与占位行回归测试。
- 新增版本一致性、CHANGELOG 精确提取、标签比较链接和 Release 工作流契约测试。

## [3.0.0] - 2026-07-28

### 变更

- **补充人物资料与来源权威收口（数据库 v9.16）**：“权威人物资料”降级为可选的“补充人物资料”，仅在平台与稳定账号 ID 精确命中且来源有歧义时作为提示，不再按昵称或文本反查。消息证据、Timeline 角色绑定与事实来源始终优先；资料不得证明人物参与、生成新事实或覆盖来源。新增、修改和删除不再标记或调度现有 Topic 重构；每个新构建任务保存独立资料快照。片段参与者和 Topic 人物关系改为应用从来源和事实引用确定性派生，不再要求 LLM 返回随后会被覆盖的顶层人物字段。迁移只清理旧的人物资料同步标记，不重写记忆。

### 新增

- **数据库健康检查与手动修复（数据库 v9.21）**：维护中心新增“数据库”页面，显式检查主记忆库和原始会话库的 SQLite 完整性、外键违规与应用级来源关系。检查过程只读，旧库已有的孤立图谱引用不会在迁移或启动时自动修复；用户可按 Timeline 勾选后从当前记忆重建图谱，或仅清理来源记忆已不存在的孤立条目，提交前会重新验证问题仍然存在并显示危险操作与备份提示。
- **可恢复的 Timeline 同 ID 重构（数据库 v9.19）**：维护中心可先检查现有 Timeline 是否仍保有完整的原始消息 ID 边界，并明确列出可重构项、阻塞原因和身份异常提示。用户只选择有完整证据的条目后，任务从原始对话重新生成并以原 ID 原位替换；失败不会覆盖旧记忆，重试可从失败项继续。每条成功重构至少同步修复其关联 Topic，也可选择重建整个记忆空间的 Topic。
- **来源约束的 Timeline 质量契约**：固定轮次、空闲收尾和手动重构统一使用消息级短引用、结构化输出与确定性质量校验。事实必须引用输入消息，未覆盖、无意义、越界或无法追溯的结果会携带具体错误校正一次；仍不合格时拒绝写入且不推进总结游标，避免用低质量摘要替换可恢复的原始对话。
- **主动与被动统一召回**：被动注入和 Agent 主动检索工具复用同一 Timeline/Topic 候选资格、正式片段补充、回退与访问联动策略。访问次数和重要性强化只在结果确实注入或返回后记录；主动工具不伪造跨轮上下文，保留其显式查询语义。
- **会话审计、清理与逻辑别名（数据库 v9.14）**：维护页新增会话审计，展示平台、Bot 账号、聊天类型、对象、最后活动时间、原始消息、未总结消息及 Timeline/Topic/正式片段/原始证据引用。支持只清理已总结旧消息、删除原始会话但保留派生记忆、以规范会话逻辑合并旧 ID，以及完整删除会话记忆链；所有跨数据库操作使用可恢复维护日志逐步执行。会话别名会同时扩展 Timeline 与 Topic 召回范围，新消息统一写入规范会话。缓存过期仅淘汰内存，不再暗示删除持久化会话；原始消息保留周期和默认关闭的自动清理策略独立配置。
- **Topic 审查与人物关系治理（数据库 v9.13）**：维护页新增待审查队列，集中展示歧义片段、候选 Topic、匹配依据、人物和 Timeline 来源，并支持合并到指定 Topic、新建、暂缓或忽略。新增带变更预览和二次确认的 Topic 合并/按正式片段拆分；主 Topic 或主分组保留原 UID，正文、原子、片段、人物索引和相关话题在同一原子发布中更新，失败时完整回滚。Topic 列表支持按人物筛选，详情中的人物关联事实与诊断来源默认折叠。
- **统一设置与维护入口（数据库 v9.12）**：AstrBot 插件配置页仅保留语言、Provider、功能开关、凭据和迁移/备份等首次启用所需选项；全部 Timeline、Topic、会话缓存、图谱、原子生命周期、索引和模型传输调参统一由 WebUI“设置”页按领域管理，原 Timeline/Topic 页面快捷参数按钮继续编辑同一份稀疏覆盖值。原“召回测试”和“模型测试”并入独立“维护”页，Topic 增量补建、重新向量化、关系重算和清空入口也从该页进入。旧配置中的非默认调参通过 v3 兼容导入一次性保留。
- **统一 Timeline 总结服务与空闲收尾**：固定轮次、手动命令和“长时间没有新对话”三种触发方式复用同一条 Timeline 生成、原子分类和溯源写入管线。空闲总结可设置等待时间、最少未总结轮次和本地扫描间隔；任务按会话串行，保存精确消息窗口、人格和重试状态，失败不会推进总结游标或丢弃原始消息，插件重启后仍可从保留范围重试。
- **有界增量管线与向量候选索引（数据库 v9.11）**：自动维护只读取当前 revision 尚未被 Topic 索引的 Timeline UID，按单批上限处理，不再回读时间邻近或相似旧 Timeline。新片段只与向量最近的旧 Topic 匹配：高置信时合并，低于门槛时新建，最优与次优过近时停止发布并进入待确认队列，避免静默生成重复 Topic。Timeline 编辑导致语义迁移时，旧 Topic 会以剩余有效来源重建，已无来源则归档，避免残留旧事实。自动任务超过总量上限时不调用模型，转为 WebUI 手动确认。
- **Topic/正式片段派生向量索引**：SQLite 继续作为权威来源，运行时按 memory space、模型签名和产物类型分页生成可丢弃 FAISS 索引。Topic 召回不再先按重要性截取 2000/5000 条；相关话题和增量合并也改为有界向量邻域。切换 Embedding 后继续拒绝旧向量，并可不调用 LLM 重新向量化。
- **稳定正式片段身份**：片段逻辑 ID 由 memory space、Timeline 身份和来源事实键确定，LLM 措辞变化不再伪造新片段；内容、来源 revision 或输入改变时递增片段 revision。关系类型统一为无层级语义的 `related`，兼容迁移旧 `related_subtopic`。Cloudflare Rerank 客户端复用同一 HTTP 连接池。
- **Timeline 运行参数面板（数据库 v9.9）**：WebUI“记忆管理”更名为“Timeline 记忆”，召回、生成、隔离、重要性衰减、自动清理与缓存调参迁入页面右上角“参数”弹窗，以稀疏覆盖保存并支持单项或全部恢复代码默认值。旧插件配置中非默认值首次启动时自动导入，请求注入方式等稳定行为仍保留在插件配置中。
- **Timeline/Topic 共享查询扩展参数**：跨轮次扩展开关、Bot 回复参与方式以及 `recent_user`/`recent_assistant` 查询权重同时显示在 Timeline 和 Topic 参数面板，共享同一份存储与运行时值。`recent_user` 默认权重从 0.65 降为 0.45；Bot 正常权重默认 0.40，低权重模式使用其一半。
- **分层召回测试**：召回测试可分别运行纯 Timeline、纯 Topic 或当前插件组合行为；Timeline 专测的 `k` 不受自动 Timeline 召回开关限制，Topic 专测也可在正式召回开关关闭时运行。会话 ID 保留自由输入，并从轻量会话目录提供随输入实时筛选的下拉候选。
- **事实级 Topic 人物关系（数据库 v9.8）**：正式片段以受约束的局部 actor ref 记录实际参与者、被提及人物及 speaker/narrator/responder/subject/mentioned/executor/requester 语义角色；无法绑定稳定账号的人物使用片段局部 unresolved ID，禁止按昵称跨片段合并。LLM 可主动请求一次原始消息补证，Topic 与事实人物关系会连同原子、片段和 Timeline 来源在同一事务中写入独立索引；Topic 详情展示身份状态、角色、置信度和事实来源。Topic 召回命中当前人物时只做可配置的轻量加分，不作为硬过滤。
- **平台规范身份与关系图独立重算**：人物资料平台改为结合 AstrBot 当前实例、历史会话和已有资料的选择列表，`aiocqhttp`、`qq_official` 等适配器别名统一锚定到逻辑平台 `qq`；单平台自动选中，多平台要求显式选择，并保留兼容但醒目标注的“不限平台”。Topic 维护面板新增仅使用已有向量和当前参数重算相关话题，不调用模型、不重建 Topic。
- **稳定人物身份与按需原始证据（数据库 v9.7）**：消息写入使用平台范围内的稳定 actor ID，修复助手回复继承触发用户昵称的问题；新 Timeline 保存结构化 `role_bindings`。正式片段保留 Bot 第一人称并绑定叙述者，旧群聊身份缺失或指代高风险时按稳定消息 ID 读取原始对话辅助消歧。Topic 元数据同步生成带片段和 Timeline 来源的参与者索引；迁移不会自动重写现有 Timeline 或 Topic。
- **正式 Topic 片段与角色锚定（数据库 v9.6）**：构建期片段从临时中间产物升级为按 Topic revision 关联的正式可追溯对象；片段保留独立 Embedding、事实、时间范围和 Timeline 来源。Timeline 原文明确按 Bot 第一人称解释，并依据稳定账号、`persona_id` 与 WebUI 人物资料锚定参与者与语义角色；当身份或指代仍存在歧义时才按需读取原始消息补证。正式召回改为 Topic 主体加相关片段，只有旧库尚无安全正式片段时才兼容回退整条 Timeline。
- **Topic 大组件结构复核**：片段匹配完成后，对达到规模阈值的语义组件调用 LLM 进行一次严格、可溯源的分组复核；允许合理的长期主题保持整体，同时拆开由相似度链条带入的通勤、工作、行程等独立事项。复核结果覆盖全部片段且不得重复或虚构引用，支持检查点复用、实时进度和失败保留原组件。
- **受影响局部 Topic 重构（数据库 v9.5）**：新增 Timeline 不再仅凭单次 Embedding 分数贪心追加到一个既有 Topic。早期实现会补入时间邻域与相似旧 Timeline；该宽范围路径已在 v9.11 被有界 delta-first 管线替代，避免记忆增长后增量任务持续扩大。
- **Topic 运行参数面板**：插件配置页只保留 Topic 构建、优先召回和自动维护开关；召回、构建、Rerank、批量、并发和容错参数移入 Topic 页面右上角“参数”。参数以稀疏覆盖保存，可单项或全部恢复代码最新默认值，并在新构建任务中保存完整参数快照以保证断点续建可复现。
- **Topic 优先正式召回（阶段 4.2）**：启用 Topic 后，自动召回与 Agent 主动回忆工具优先按当前记忆空间检索活跃 Topic，并只附带少量相关 Timeline；没有可用 Topic 或 Topic 检索异常时自动回退阶段 4.1 的纯 Timeline 管线。Topic 使用构建时保存的 Embedding、关键词和可选 Rerank 精排，不调用 LLM；当前上下文已覆盖大部分来源时抑制 Topic，部分覆盖只降低权重。召回测试页展示 Topic 层、实际阈值和来源覆盖诊断。
- **结构化 Timeline 召回管线（阶段 4.1）**：当前消息、最近用户消息与可选 Bot 回复改为独立加权查询；Bot 回复支持不查询、低权重和正常查询。召回先扩大候选集，再执行相关度门槛、相对过滤、中文文本 MMR 和当前上下文来源重叠抑制，最终数量允许少于 `top_k`；召回测试页展示查询分支、实际阈值和候选淘汰原因。
- **Rerank 并发控制**：新增 `topic_memory.rerank_concurrency`（默认 1、范围 1–32），片段匹配阶段可并行调用 Cloudflare 或 AstrBot Rerank Provider；进度栏显示完成数、活跃请求数与并发上限，任一请求失败时仍按既有策略整轮回退 Embedding。
- **断点任务取消与进度清理**：Topic 构建出现可恢复断点时，WebUI 同时提供“取消任务”；确认后删除该运行保存的扫描、片段、匹配、合成和检查点数据，并保留已正式落库的 Topic，避免破坏构建前数据。
- **Topic 相关子话题图（数据库 v9.4）**：保持叶子 Topic 内容独立，通过互为语义近邻的 `related_subtopic` 关系连接同一事件下的行程、天气、住宿、现场活动与后续恢复等子话题；详情浮窗可直接查看并跳转相关 Topic。
- **自动 Topic 记忆层（数据库 v9.3，实验性）**：LLM 将宽时间窗口拆为可溯源片段，再通过 Embedding 与可选 Rerank 跨时间归并；Topic 拥有独立原子、稳定 UID/revision，以及 `Topic → Timeline → 事实指纹` 来源链。
- **全量与增量维护**：首次增量任务自动转为全量扫描；后续新增 Timeline 可增量合并到已有 Topic。编辑 Timeline 时保留旧 Topic 直到局部重建原子发布成功，删除 Timeline 则保守标记依赖 Topic 并触发维护。
- **Topic WebUI**：新增只读 Topic 列表、原子与 Timeline 来源查看、全量/增量手动构建及实时进度显示。
- **可选 Rerank Provider**：新增 `provider_settings.rerank_provider_id`，未配置时保持纯 Embedding 匹配。
- **Cloudflare Workers AI Rerank**：AstrBot 尚未支持 Cloudflare Rerank Provider 时，插件可直接调用 `@cf/baai/bge-reranker-base`；原样使用接口返回的 `[0, 1]` 相关度，支持 429/5xx 重试、超时控制和失败后回退 Embedding。
- **模型测试 WebUI**：以独立卡片展示插件运行时实际使用的 LLM、Embedding、Rerank，标明显式配置、AstrBot 默认回退或 Cloudflare 内置来源，并可分别发起连接测试。
- **WebUI 权威人物资料与身份提示词**：新增“人物资料”页面，以平台稳定账号 ID 为主键管理姓名、性别、代词和备注；人物条目以默认折叠的紧凑列表展示，点击后展开编辑。资料独立保存到插件数据目录并在保存后立即更新 Timeline 与 Topic 生成链路；插件配置中不增加人物资料字段。提示词禁止从昵称、语气、兴趣或人格设定推断参与者身份，未知时改为重复昵称。本阶段不进行生成后的确定性身份校验。

### 兼容性

- Topic 功能默认关闭，v9→v9.11 迁移只创建结构、回填片段逻辑 ID 并规范关系类型，不调用模型、不生成 Topic，也不改变现有 Timeline/图谱。旧 Topic 的 v9.8 人物关系表保持为空，并在下一次全量或局部重构时回填；v9.5 旧片段因尚未经过角色规范，不会直接作为片段补充。

### 修复

- **共享图谱边误删与外键违规（数据库 v9.21）**：新增 `graph_edge_sources` 多对多证据表，跨 Timeline 合并的语义边不再只保留单一 `source_memory_id`。删除或批量清理 Timeline 时只撤销该来源的边证据，并从剩余来源确定性重算聚合权重与置信度；最后一个来源消失时才删除规范边。GraphStore 每个 SQLite 连接统一启用外键检查，避免继续生成静默孤立引用。
- **Topic 片段身份碰撞与情绪人物断链（数据库 v9.20）**：正式片段继续以 Timeline 和来源事实作为稳定身份，但同一宽泛来源事实确实拆成多个语义片段时，增加确定性语义区分以避免两个活动片段共用逻辑 ID；普通措辞变化仍不改变身份。情绪事件会复用事实中唯一的同名局部人物，发布前强制校验 `Topic 情绪 → 人物索引 → 正式片段 → Timeline` 来源链。迁移仅对昵称可唯一对应的旧记录原位修复，不调用模型、不改写 Topic 正文。
- **Topic 非人物实体误索引**：片段提取契约明确只允许人、助手人格和可执行行为的人类群体生成人物关系；天气、季节、时间、地点、物品、产品、组织、政策和抽象概念不再因为被提及而产生 actor ref。
- **Topic 参数与构建错误界面可读性**：构建失败时同时展示具体处理环节、环节说明和原始异常；Topic 参数按板块强化视觉分组，每项增加用途说明，统一“默认/自定义”徽标与“默认值”文案，并在保存成功后自动关闭弹窗。Topic 列表为标题释放更多宽度，取消加粗并允许最多显示两行。
- **Topic 关系误连与稠密节点挤占**：共享宽 Timeline 降为弱证据，不能再单独促成关系；关系算法 v6 用统一的“覆盖收益 + 关系质量”目标替代多轮顺序敏感贪心，并以不降低覆盖为前提全局选择孤立点换边。中文关键词的重叠 n-gram 只计一次，人物代词、身份、边界等抽象连接词不再充当独立证据；稀有精确概念和 `Expo2026` 等标识仍可保留低分但明确的关系。参与者索引统一平台别名，并以人格锚定 Bot 身份，避免同一用户或 Bot 因适配器名和回退来源重复出现。
- **单人对话片段因通用人物称谓整体降级**：当角色映射中恰好只有一个稳定人类参与者时，模型偶发输出的“用户/对方/叙述者”会确定性替换为映射姓名并记录修复审计；群聊或身份不唯一时仍拒绝猜测并沿用安全回退，避免一处可修复称谓导致整条正式片段无法用于 Timeline 补充。
- **Topic 身份证据断点与相关话题覆盖**：修复扫描候选写入断点时遗漏 `role_bindings`、稳定消息范围和溯源字段，导致旧 Timeline 即使存在完整消息 ID 也无法回填原始证据的问题；旧断点恢复时会从正式 Timeline 与来源表补齐缺失字段。参与者索引按原始消息、Timeline 绑定、权威资料回退和人格回退分别记录来源与置信度。相关话题图改为多信号、无向、无层级的稀疏连接，互为 Top-N 作为加分与核心边保护条件，不再作为唯一硬门槛。
- **Topic 召回 Rerank 绝对分过度压制强语义命中**：新增运行参数 `recall_rerank_weight`（默认 0.35），替代固定 0.55 权重；Rerank 为零时仍保留 65% 的 Embedding/关键词基础相关度，权重设为 0 时不发起 Rerank 请求。召回诊断同时显示融合前基础分与原始 Rerank 分，便于针对不同 Provider 的分数尺度调整。
- **Topic 召回中等相关候选被绝对门槛全部误杀**：默认最低相关度由 0.42 调整为 0.32，继续保留相对门槛、MMR 和最大召回数约束；召回诊断增加 Embedding、关键词及 Rerank 分项分数。Topic WebUI 运行参数现在也会统一控制自动召回、主动记忆工具和召回测试中的 Topic 数量及 Timeline 补充数量，不再从已移除的旧配置字段取值。
- **跨轮扩展重复当前消息与无效去重**：修正把时间升序历史误当成倒序、跳过最旧消息并再次拼入当前消息的问题；MMR 改为在候选截断前执行。只有最终实际注入的记忆才增加访问次数，v2 Timeline 注入不再重复输出已包含在正文中的关键事实。
- **并发 Topic 合成进度与维护入口**：并发合成阶段按实际完成的组件数推进阶段进度和总体进度，不再在长时间合成期间固定停留于 75%；同阶段乱序回调会保持单调进度。WebUI 将固定的“增量维护（24h）”主按钮收拢为“维护”面板；面板检测当前 revision 尚未被活跃 Topic 索引的 Timeline，默认全选并在用户确认后仅补建选中项。
- **Topic 泛化质量与可解释分数**：片段提示词改为单一检索意图边界；相关子话题关系使用全库词频、加权正文重合与来源组合证据，并过滤日期、时刻等结构词。片段匹配新增完整候选排序与双向相对排名证据；两个已形成的组件合并时按规模缓慢提高平均一致性要求，减少绝对分数饱和导致的保守拆分，同时阻止边界桥形成超大 Topic；Topic/原子置信度按独立时间簇和来源数量进行收缩校准。
- **Topic 匹配参数解耦与审计**：候选扫描阈值不再隐式控制 Rerank 候选线和组件凝聚度；新增独立最低两两/平均相似度参数。构建断点记录单片段 Topic 是因候选不足、未通过双向 Rerank，还是被组件凝聚度拒绝，便于后续使用真实样本调优。
- **内置 Cloudflare Rerank 启动期误判未启用**：Rerank 初始化从 LLM Provider 等待流程中解耦，避免静默等待聊天模型时提前返回并跳过 Cloudflare 客户端；`provider_settings.rerank_provider_id` 留空时内置 Cloudflare 仍可独立启用，二者同时配置时内置 Cloudflare 优先。修复 `topic_memory.llm_concurrency=30` 超出隐藏校验上限后导致整份插件配置回退默认值、连带关闭 Cloudflare 的问题，并将允许范围明确为 1-64。模型测试页会显示安全的初始化错误，不再将配置异常笼统标为“未启用”。
- **Topic 全量构建被无效原子指纹整体中断**：LLM 返回未知或被改写的 `source_atom_fingerprints` 时，安全剔除无效引用；事实内容与来源原子完全一致时确定性恢复正确指纹，否则保留 Timeline 来源并降级为事实指纹溯源。未知 Timeline 和越界来源不会被采纳；无法局部修复时整批回退为输入 Timeline 的确定性片段。
- **Topic 构建进度与重复启动**：新增覆盖六个处理阶段的总体进度；候选扫描完成不再显示误导性的 `running · completed`，最终异常会明确更新为 `failed · failed`。活动任务可在页面刷新后恢复轮询，构建期间按钮自动禁用，后端也会阻止重复启动。
- **Topic 合成遗漏来源导致全量失败**：模型未让原子覆盖全部已知片段时，使用输入中的事实原子确定性补齐并记录修复审计；未知片段或事实引用会被剔除，并由可验证输入补回。宽候选组先按 `topic_memory.fragment_extraction_batch_size` 提取，超大语义组件再按 `topic_memory.synthesis_batch_size` 分层合成，保持单一 Topic 与原始溯源，避免一次请求携带过大的上下文。
- **长任务详细进度**：Topic 页面在 LLM 运行期间显示当前候选组或语义组件、组件/批次片段数、分层级别、调用序号、总耗时以及距上次进度时间，便于区分长请求与任务停滞。
- **Topic LLM 并发控制**：新增 `topic_memory.llm_concurrency`（默认 2）；候选组、组内片段提取批次及同一合成层级均可并发调用 Provider，并由共享信号量限制全局并发。候选组进度按实际完成数聚合，额外显示活跃组数量；配置为 1 可恢复串行模式。
- **Topic 构建断点续建**：失败、取消或插件重启中断的任务可在 WebUI 使用原 `run_uid` 继续；候选组片段、Embedding、片段匹配、每个 Topic 组件合成及已完成物化均持久化检查点。输入、Prompt、Provider 或模型变化时，对应检查点自动失效并安全重算。
- **可恢复的 LLM 结构错误**：合成顶层遗漏/多写 `fragment_uids`、原子引用未知片段或事实、缺少标题摘要、无效原子数组，以及片段提取返回无效 JSON/越界来源时不再直接中断。系统只保留输入中可验证的来源，并以原 Timeline 片段或事实原子确定性补齐；Provider 请求最终失败和数据库错误仍会终止任务并保留断点。
- **Topic 提示词与溯源协议**：片段提取和 Topic 合成改用 `T1.A1`、`F1` 等批次内短引用，LLM 不再抄写真实 UUID、事实 UID、原子指纹或可由事实推导的片段范围；后端确定性恢复完整来源链。合成输入会剔除嵌套溯源元数据，并在 JSON 或引用校验失败时携带具体错误自动校正一次，减少 Token、超时和长标识抄写错误。
- **Topic 列表紧凑展示**：列表仅显示标题，整行支持鼠标点击及键盘 Enter/空格打开大尺寸来源详情浮窗；浮窗支持点击外部、右上角关闭按钮或 Escape 关闭。Topic 主页面贴合可视区域，列表内容改为内部滚动，避免详情拉长整个页面。
- **Topic 重复全量构建确认**：当前记忆空间已有 Topic 时，再次点击“全量构建”会显示二次确认，可选择保留现有 Topic 并更新，或先清空该空间的 Topic、原子、来源、索引及构建断点后从零构建；首次构建仍可直接启动。Topic 概览同步改为紧凑横向布局，为列表释放更多可视高度。
- **Topic 跨话题过度归并与来源空链**：Rerank 候选改为按 Embedding 排序并要求双向确认，组件聚类增加最差跨成员相似度与平均凝聚度约束，避免单链接传递将大量异质片段合成全局生活摘要；片段与最终 Topic 强制保证每条 Timeline 至少支撑一个事实原子，原子指纹未覆盖的来源会确定性补充事实指纹。匹配算法版本纳入断点哈希，旧聚类检查点不会被误复用。
